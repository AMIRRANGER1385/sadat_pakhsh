# فروشگاه نایلکس سادات

فروشگاه فارسی RTL با Next.js App Router، React، Tailwind CSS و Prisma 6 / SQLite. شامل ۸ محصول نمونه با تصاویر SVG محلی، قیمت خرده و عمده، سبد خرید، سفارش، زرین‌پال، حساب عمده و پنل مدیریت.

## اجرای اولیه

Node.js نسخه ۲۲ یا ۲۴ نصب باشد. در پوشه پروژه:

```sh
npm install
npm run setup
npm run dev
```

سپس http://localhost:3000 را باز کنید. فایل index.html نقطه ورود نیست؛ پروژه به سرور Next.js نیاز دارد.

در PowerShell اگر اجرای npm.ps1 مسدود بود، از `npm.cmd` به جای `npm` استفاده کنید. اگر nvm پیام نسخه غیرفعال داد، `nvm use 24.20.0` را اجرا کنید (این نسخه در سیستم فعلی نصب است).

`setup` فایل `.env`، دیتابیس و محصولات نمونه را ایجاد می‌کند. تکرار آن، محصول یا حساب تکراری نمی‌سازد و رمز مدیر موجود را تغییر نمی‌دهد.

## ورود مدیر

به http://localhost:3000/admin بروید. نام کاربری اولیه `admin` و رمز تصادفی در مقدار `ADMIN_PASSWORD` فایل `.env` است. این فایل محرمانه و خارج از Git است. برای تعیین رمز دلخواه در نصب جدید، قبل از setup فایل `.env.example` را به `.env` کپی و رمز حداقل ۱۲ کاراکتری قرار دهید. تغییر متغیر پس از ساخت حساب، رمز ذخیره‌شده را تغییر نمی‌دهد.

پنل شامل محصول و دسته‌بندی، موجودی، حداقل تعداد عمده، سفارش‌ها، تأیید/رد مشتری عمده، ارسال ثابت و آمار پرداخت‌های موفق است. حذف محصول به صورت غیرفعال‌سازی انجام می‌شود تا سوابق سفارش حفظ شوند. برای تصاویر جدید، در فرم محصول از «عکس محصول» فایل JPEG/PNG/WebP تا ۵ مگابایت را انتخاب و پس از آپلود، محصول را ذخیره کنید. تصاویر نمونه محلی‌اند و نیازی به سرویس خارجی ندارند.

## پرداخت زرین‌پال

در `.env`:

```dotenv
APP_URL="http://localhost:3000"
ZARINPAL_MERCHANT_ID="کد مرچنت دریافتی از زرین‌پال"
ZARINPAL_SANDBOX="true"
```

سرور را پس از تغییر متغیرها دوباره اجرا کنید. بدون مرچنت، خرید و مشاهده سبد ممکن است اما پرداخت غیرفعال است. اتصال آزمایشی هم به دسترسی شبکه و پذیرش مرچنت توسط سرویس Sandbox نیاز دارد. تراکنش واقعی در این پروژه آزمایش نشده است.

برای تولید، `APP_URL` را به آدرس HTTPS دامنه بدون اسلش پایانی و `ZARINPAL_SANDBOX` را به `false` تغییر دهید. مرچنت واقعی و دامنه را در پنل زرین‌پال تأیید کنید. callback برابر `https://YOUR-DOMAIN/api/payment/callback` است.

قیمت‌ها در دیتابیس تومان‌اند و هنگام درخواست و تأیید درگاه در ۱۰ ضرب می‌شوند. مبلغ و قیمت عمده در سرور از دیتابیس محاسبه می‌شود. هیچ اطلاعات کارت بانکی در سرور ذخیره نمی‌شود. بازگشت موفق مرورگر به تنهایی پرداخت را تأیید نمی‌کند؛ verify سرور لازم است و callback تکراری دوباره موجودی را کم نمی‌کند.

موجودی هنگام ایجاد سفارش در تراکنش دیتابیس رزرو می‌شود. خطای ایجاد درخواست درگاه رزرو را برمی‌گرداند. سفارش دارای authority که کاربر پرداختش را رها کرده، برای جلوگیری از فروش بیش از موجودی، رزرو می‌ماند؛ آزادسازی خودکار سفارش‌های رهاشده و تطبیق دوره‌ای تراکنش‌ها هنوز پیاده‌سازی نشده است. پیش از فروش عمومی، گردش عملیاتی بررسی این سفارش‌ها را تکمیل کنید. وضعیت پرداخت فقط از درگاه ثبت می‌شود؛ مدیر می‌تواند سفارش پرداخت‌شده را ارسال و سپس تحویل‌شده کند.

مستند نمونه رسمی درخواست: https://github.com/ZarinPal-Lab/Zarinpal-RestAPI-Sample-php/blob/master/Request.php

## استقرار

### سرور یا هاست ایرانی با Node.js

هاست باید امکان اجرای دائمی Node.js داشته باشد؛ هاست صرفاً PHP یا آپلود HTML کافی نیست.

1. کد و lockfile را منتقل و `npm ci` اجرا کنید.
2. متغیرهای `.env` را با دامنه، رمز و مرچنت واقعی تنظیم کنید.
3. `npm run setup`، سپس `npm run build` و `npm start` اجرا کنید.
4. سرویس را با systemd یا PM2 دائمی و با reverse proxy روی دامنه و HTTPS منتشر کنید.
5. فایل SQLite را در دیسک دائمی نگه دارید؛ فقط یک نمونه سرور اجرا کنید. از دیتابیس نسخه پشتیبان سازگار با SQLite تهیه کنید و بازیابی را آزمایش کنید.

### Vercel

SQLite محلی برای ذخیره دائمی در Vercel مناسب نیست. ابتدا PostgreSQL مدیریت‌شده تهیه کنید، provider در `prisma/schema.prisma` را به `postgresql` تغییر دهید و `DATABASE_URL` را تنظیم کنید. migration مخصوص PostgreSQL را بسازید و در استقرار `prisma migrate deploy` اجرا کنید؛ migration مربوط به SQLite قابل استفاده مستقیم نیست. داده موجود باید جداگانه منتقل شود. سپس پروژه را در Vercel import کنید، متغیرها را تنظیم و build را اجرا کنید. seed را یک‌بار در محیط کنترل‌شده انجام دهید. در استقرار چندنمونه‌ای، محدودسازی درخواست فعلی باید از نظر هم‌زمانی سخت‌گیرانه‌تر شود.

راهنمای رسمی استقرار Next.js: https://nextjs.org/docs/app/getting-started/deploying

## بررسی‌ها

```sh
npm run typecheck
npm test
npm run build
```

تست‌ها مرز قیمت عمده، حساب تأییدشده و ارسال رایگان را پوشش می‌دهند. پیش از فروش عمومی، تراکنش Sandbox سرتاسری، سفارش هم‌زمان، تأیید مشتری عمده، موبایل و بازیابی دیتابیس را بررسی کنید. شماره تماس، نشانی و معرفی شرکت را در «پنل مدیریت ← اطلاعات شرکت» وارد کنید. تصاویر و قیمت‌های نمونه باید با کالاهای واقعی جایگزین شوند.


راهنمای افزودن کالا، اطلاعات شرکت و گزارش اصلاحات SEO و امنیت: [SECURITY-SEO.md](SECURITY-SEO.md). رمز را از «امنیت حساب» در پنل مدیریت تغییر دهید.


## آپلود، کاربران و انتشار روی دامنه

آپلود مستقیم در «محصولات ← محصول جدید/ویرایش» فعال است. پوشه پیش‌فرض `.data/uploads` است و با `UPLOAD_DIR` قابل تغییر است؛ فایل‌ها به‌صورت WebP از `/media/...` ارائه می‌شوند. پوشه باید دائمی و خارج از public باشد. از آن همراه دیتابیس پشتیبان بگیرید.

اطلاعات حساب کاربران در دیتابیس ذخیره می‌شود. بخش «کاربران و مشتریان» مشخصات حساب‌ها و «سابقه ورود» ۱۰۰ رویداد اخیر ورود، ثبت‌نام و تغییر رمز را نشان می‌دهد. اطلاعات مرورگر از هدر درخواست است و هویت دستگاه را اثبات نمی‌کند. تاریخچه حداکثر ۹۰ روز نگهداری و در رویداد احراز هویت بعدی پاک‌سازی می‌شود؛ حساب کاربر حذف نمی‌شود. رمز خام، IP یا اطلاعات کارت در تاریخچه ذخیره نمی‌شود.

راهنمای گام‌به‌گام هاست شما: [DEPLOY-CPANEL.md](DEPLOY-CPANEL.md). تنظیمات نمونه برای `sadatpakhsh.ir` در `deploy/cpanel.env.example` است. فایل startup در Passenger برابر `app.js` است.
