# فروشگاه نایلکس سادات — نسخه PHP برای cPanel

برای انتقال تغییرات با Git: [راهنمای انتشار Git در cPanel](DEPLOY-GIT-FA.md). فایل `.cpanel.yml` و اسکریپت انتشار آماده‌اند؛ اتصال مخزن و اجرای انتشار در هاست هنوز انجام نشده است.

راهنمای sitemap پویا و معرفی دامنه به گوگل: [SEO-SITEMAP-FA.md](SEO-SITEMAP-FA.md). آدرس نقشه پس از انتشار: `https://sadatpakhsh.ir/sitemap.xml`.

این نسخه با PHP 8.2 و MySQL/MariaDB اجرا می‌شود و برای هاست لینوکسی شما که Node.js ندارد آماده شده است. برای انتشار آن **npm install، npm run dev و Composer لازم نیست**. سایت پس از نصب روی هاست، حتی با خاموش‌بودن کامپیوتر شما در دسترس خواهد بود.

## از کجا شروع کنم؟

1. بسته [naylex-sadat-php82.zip](dist/naylex-sadat-php82.zip) را بردارید.
2. اتصال دامنه و SSL را طبق بخش بعد بررسی کنید.
3. دیتابیس جدید بسازید، فایل‌ها را در مسیرهای توضیح‌داده‌شده بگذارید و config.php مخصوص هاست بسازید.
4. نصب را از `https://sadatpakhsh.ir/install` انجام دهید و حساب مدیر بسازید.
5. اطلاعات شرکت، محصولات، درگاه و Cron را تنظیم و سناریوهای خرید را تست کنید.

کد خصوصی در `php-store/naylex-app` و فایل‌های قابل نمایش در `php-store/public_html` هستند. `.env` برای نسخه قبلی Next.js است؛ تنظیمات PHP از `naylex-app/config.php` خوانده می‌شود. راهنمای قدیمی در [README-NEXTJS.md](README-NEXTJS.md) نگهداری شده و دستورهای آن برای هاست PHP شما نیست.

## اتصال دامنه sadatpakhsh.ir به هاست

اطلاعاتی که قبلاً از هاست ارائه کرده‌اید: نام‌سرورها `ns1box407.parsvds.com` و `ns2box407.parsvds.com`، آی‌پی `87.107.55.181` و پیشوند حساب `rrjjboqm`. این‌ها باید با اطلاعات فعلی پنل میزبان تطبیق داده شوند؛ اتصال یا صحت فعلی DNS از داخل این پروژه تأیید نشده است.

1. در پنل ثبت‌کننده دامنه، بخش Nameservers/DNS Servers، نام‌سرورهای اعلام‌شده از طرف هاست را قرار دهید. این کار در `.env` یا کد سایت انجام نمی‌شود. اگر دامنه ایمیل یا سرویس فعال دارد، رکوردهای آن را پیش از تغییر DNS حفظ کنید.
2. در cPanel بخش **Domains** مطمئن شوید `sadatpakhsh.ir` به حساب اضافه شده است و **Document Root** آن را یادداشت کنید. در حالت معمول `/home/rrjjboqm/public_html` است؛ مقدار پنل ملاک است.
3. پس از انتشار DNS، در **SSL/TLS Status** وضعیت گواهی دامنه را بررسی کنید و در صورت وجود گزینه، AutoSSL را اجرا کنید. اگر امکانش نیست، از میزبان بخواهید SSL دامنه را فعال کند. [راهنمای رسمی SSL در cPanel](https://docs.cpanel.net/cpanel/security/ssl-tls-status/)
4. وقتی HTTPS بدون خطای گواهی باز شد، هدایت HTTP به HTTPS را از گزینه **Force HTTPS Redirect** دامنه، در صورت ارائه میزبان، فعال کنید. آدرس اصلی این پروژه `https://sadatpakhsh.ir` بدون www است؛ اگر www را هم استفاده می‌کنید، آن نیز باید DNS و گواهی معتبر داشته باشد.

پورت `8085` فقط سرور محلی است. برای بازکردن سایت منتشرشده از `https://sadatpakhsh.ir` استفاده کنید، نه آی‌پی با پورت 8080 یا 8085. این برنامه برای ریشه دامنه یا زیردامنه تنظیم شده، نه آدرس زیرپوشه‌ای مانند `/shop`.

## چه چیزهایی را آپلود نکنم؟

کل پوشه پروژه را به public_html منتقل نکنید. `.env`، `.runtime`، `node_modules`، `.git`، اطلاعات مدیر محلی، دیتابیس آزمایشی و config.php محلی جزو فایل‌های انتشار نیستند. بسته ZIP خودکار config.php و storage را حذف می‌کند. روی هاست config.php جدید بسازید.

برای تهیه بسته جدید پس از تغییر کد، روی کامپیوتر از ریشه پروژه اجرا کنید:

```powershell
python scripts/package-php.py
```

Python فقط برای ساخت بسته روی کامپیوتر استفاده می‌شود؛ روی هاست لازم نیست. بسته از قبل ساخته‌شده نیز قابل استفاده است.

## امکانات و وضعیت فعلی

- فروشگاه فارسی، دسته‌بندی، فیلتر قیمت، صفحه محصول و قیمت خرده/عمده.
- افزودن اولیه در صفحه محصول، سپس کنترل مثبت و منفی؛ پیش‌نمایش تصویری سبد و هدر ثابت.
- ثبت‌نام و ورود با حساب یکپارچه مشتری، ثبت سابقه ورود و حداقل رمز ۸ کاراکتر. مدیر می‌تواند TOTP 2FA و کدهای بازیابی را از پنل امنیت فعال کند.
- پنل محصولات و آپلود JPEG/PNG/WebP، موجودی، سفارش‌ها، دسته‌بندی‌ها، اطلاعات شرکت و ارسال.
- محاسبه مبلغ روی سرور، رزرو موجودی و آزادسازی زمان‌بندی‌شده، و اتصال کدنویسی‌شده زرین‌پال.
- بازیابی پیامکی **غیرفعال** است؛ سرویس هنوز انتخاب نشده و ارسال کد پیاده‌سازی نشده است. استرداد خودکار وجه نیز فعال نیست.

تست‌های محلی جای بررسی روی هاست را نمی‌گیرند. انتشار، تنظیم DNS، SSL و تراکنش واقعی روی حساب هاست شما توسط این پروژه انجام نشده است.

## انتقال داده، ارتقا و برگشت به نسخه قبل

نصب تازه محصولات نمونه می‌سازد؛ محصولات و کاربران لوکال خودکار به هاست منتقل نمی‌شوند. اگر داده واقعی در لوکال دارید، قبل از نصب تازه باید انتقال SQL دیتابیس و تصاویر `storage/uploads` با حفظ شناسه‌ها برنامه‌ریزی شود. داده‌های آزمایش، نشست‌ها و حساب‌های آزمایشی را همراه داده واقعی منتشر نکنید.

برای به‌روزرسانی سایتی که همین نسخه PHP روی آن نصب است، اول SQL دیتابیس و فایل‌های سایت را پشتیبان بگیرید. فایل‌های کد جدید را جایگزین کنید اما **config.php، storage و installed.lock موجود را حفظ کنید**. نصب‌کننده را دوباره اجرا نکنید. برای برگشت، نسخه سازگار فایل‌ها و دیتابیس را با هم از پشتیبان برگردانید؛ بازگردانی دیتابیس قدیمی می‌تواند سفارش‌های ثبت‌شده بعد از پشتیبان را از بین ببرد، پس هنگام انتقال دریافت سفارش را متوقف کنید.

## آزمون انتشار قبل از فروش عمومی

در دامنه اصلی با مرورگر ناشناس ثبت‌نام کنید، خارج شوید و دوباره وارد شوید؛ یک محصول را اضافه و کم کنید، صفحه را تازه کنید، اطلاعات شرکت را بررسی کنید و یک تصویر آزمایشی در پنل آپلود کنید. قیمت عمده در آستانه تعیین‌شده و هزینه ارسال را کنترل کنید. سپس پرداخت موفق و ناموفق Sandbox، پیگیری سفارش و گزارش Cron را بررسی کنید. فقط بعد از تأیید این موارد درگاه را به حالت واقعی ببرید.

اگر خطای 500 مشاهده شد، گزارش خطای PHP در cPanel را بررسی کنید؛ اطلاعات محرمانه و فایل config.php را عمومی منتشر نکنید. اگر سایت قدیمی نمایش داده می‌شود، Document Root، فایل index قدیمی و کش مرورگر/هاست را بررسی کنید.

# نصب نسخه PHP نایلکس سادات

این بسته با **PHP 8.2 و MySQL/MariaDB** اجرا می‌شود؛ Node.js، npm و Composer لازم نیست. نسخه قبلی Next.js جدا باقی مانده است. این بسته را با فایل‌های Next.js مخلوط نکنید.

بررسی محلی: نصب روی دیتابیس جدا، ۴۵ آزمون HTTP، ۱۶ تست منطق PHP/MySQL و بررسی نحوی همه فایل‌های PHP موفق بوده‌اند. محیط تست PHP 8.2 و MariaDB بوده است. Apache/cPanel هاست و تراکنش واقعی زرین‌پال هنوز در محیط مقصد تست نشده‌اند.

## ۱. دیتابیس جدا بسازید

در cPanel → Manage My Databases:

1. در New Database فقط `naylex` وارد کنید؛ نام کامل معمولاً `rrjjboqm_naylex` می‌شود. اگر قبلاً وجود دارد، نام تازه‌ای مانند `naylex_shop` انتخاب کنید.
2. در MySQL Users یک کاربر جدید بسازید؛ مثلاً پسوند `naylex` با رمز قوی جدید. نام کامل نمایش‌داده‌شده را یادداشت کنید؛ ممکن است `rrjjboqm_naylex` باشد.
3. در Add User To Database، **همان کاربر جدید** را به **همان دیتابیس جدید** اضافه کنید؛ ALL PRIVILEGES و Make Changes را بزنید.

دیتابیس `rrjjboqm_wp_5eyir` و کاربر وردپرس فعلی را تغییر یا حذف نکنید. نصب‌کننده اگر جدول غیرمرتبط ببیند متوقف می‌شود. رمز دیتابیس را در گفتگو نفرستید.

## ۲. فایل‌ها را در جای صحیح قرار دهید

بسته دو پوشه دارد:

```text
/home/rrjjboqm/
├── naylex-app/              ← کد خصوصی، تنظیمات و ذخیره‌سازی
│   ├── config.example.php
│   ├── bootstrap.php
│   └── ...
└── public_html/             ← فقط محتویات پوشه public_html بسته
    ├── index.php
    ├── .htaccess
    ├── .user.ini
    ├── assets/
    ├── products/
    └── fonts/
```

در File Manager، پوشه `naylex-app` را در **Home حساب، کنار public_html** قرار دهید، نه داخل آن. محتوای پوشه `public_html` بسته در ریشه وب دامنه قرار می‌گیرد. فایل‌های مخفی را با Settings → Show Hidden Files نمایش دهید.

چون روی هاست شما دیتابیس وردپرس وجود دارد، ممکن است سایت فعلی نیز فعال باشد. **قبل از جایگزینی index.php و .htaccess از فایل‌ها و دیتابیس سایت فعلی پشتیبان کامل بگیرید.** ابتدا نصب آزمایشی روی زیردامنه با document root جدا انجام دهید. سایت فعلی را بدون برنامه انتقال حذف نکنید. این پروژه هیچ تغییر خودکاری روی وردپرس نمی‌دهد.

اگر Document Root دامنه با `/home/rrjjboqm/public_html` متفاوت است، در فایل عمومی `index.php` مقدار مسیر برنامه را صریح کنید:

```php
$appPath = '/home/rrjjboqm/naylex-app';
require $appPath . '/bootstrap.php';
```

## ۳. PHP و تنظیمات محرمانه

در Select PHP Version نسخه 8.2 با آخرین patch ارائه‌شده میزبان و افزونه‌های زیر فعال باشند:

```text
pdo_mysql, mbstring, curl, fileinfo, gd, session
```

EXIF اختیاری است و برای اصلاح چرخش عکس JPEG استفاده می‌شود. GD باید WebP را پشتیبانی کند. افزونه‌ها و مجوزهای هاست توسط میزبان کنترل می‌شوند. حد فایل آپلود ۵ مگابایت، حد POST برابر ۶ مگابایت و memory_limit دست‌کم ۲۵۶ مگابایت تنظیم شود؛ `.user.ini` همراه بسته این مقادیر را پیشنهاد می‌دهد. در بعضی هاست‌ها باید از PHP Options پنل تنظیم شوند.

در `naylex-app` فایل `config.example.php` را کپی و نام کپی را **config.php** بگذارید. مقادیر زیر را پر کنید:

```php
'app_url' => 'https://sadatpakhsh.ir',
'db_host' => 'localhost',
'db_port' => 3306,
'db_name' => 'rrjjboqm_naylex',
'db_user' => 'rrjjboqm_naylex',
'db_password' => 'رمز کاربر دیتابیس جدید',
'install_key' => 'کلید تصادفی و محرمانه حداقل ۳۲ کاراکتری',
'allow_install' => true,
'merchant_id' => '',
'sandbox' => true,
```

نام‌های واقعی ایجادشده در cPanel ملاک‌اند. DB_HOST معمولاً localhost است؛ اگر میزبان مقدار دیگری داده همان را استفاده کنید. کلید نصب را با Password Generator پنل بسازید (مثلاً ۴۸ کاراکتر انگلیسی و عدد) و فقط خودتان نگه دارید. رمز مدیر با رمز دیتابیس و کلید نصب متفاوت است. هیچ رمز مشترک پیش‌فرضی در بسته وجود ندارد.

فایل config.php و پوشه storage عمومی نیستند. پوشه `naylex-app/storage` باید برای **کاربر PHP خود حساب** قابل نوشتن باشد؛ از مجوز 777 استفاده نکنید. معمولاً 700 برای پوشه خصوصی و 600 برای config کافی است؛ اگر PHP تحت کاربر دیگری اجرا می‌شود، میزبان باید دسترسی درست را تنظیم کند. مسیر پیش‌فرض storage در config آماده است.

## ۴. نصب از مرورگر

ابتدا DNS و SSL دامنه برقرار باشد. این آدرس را باز کنید:

```text
https://sadatpakhsh.ir/install
```

کلید نصب، نام کاربری مدیر مانند `admin` و **رمز جدید حداقل ۱۲ کاراکتری** را وارد کنید. جدول‌ها، ۸ محصول نمونه و حساب مدیر ساخته می‌شوند. سپس:

- مقدار `allow_install` را در config.php برابر **false** کنید.
- کلید نصب را از config.php پاک کنید.
- فایل `storage/installed.lock` را نگه دارید؛ جلوی نصب مجدد را می‌گیرد.
- از `https://sadatpakhsh.ir/admin` وارد شوید.

از «محصولات» کالا و عکس اضافه کنید، «اطلاعات شرکت» را کامل کنید و در «سابقه ورود» رویدادهای جدید را ببینید. عکس هنگام ذخیره محصول پردازش و در storage/uploads ذخیره می‌شود؛ اطلاعات حساب و سفارش‌ها در MySQL می‌مانند. تاریخچه ورود از این نصب به بعد ایجاد می‌شود، نه از گذشته‌ای که در این دیتابیس نیست.

## ۵. دامنه و درگاه

دامنه اصلی `sadatpakhsh.ir` است. NSهای اعلام‌شده شما `ns1box407.parsvds.com` و `ns2box407.parsvds.com` هستند؛ باید در پنل ثبت دامنه روی NSهای همین سرویس فعال تنظیم شده باشند. IP اعلام‌شده `87.107.55.181` را فقط پس از تطبیق با IP سرویس در رکورد A استفاده کنید. این مقادیر توسط شما اعلام شده‌اند و در این محیط تغییر داده نشده‌اند.

در cPanel SSL/AutoSSL و سپس Force HTTPS Redirect را فعال کنید. www به دامنه اصلی بدون www هدایت شود. اگر روی زیردامنه تست می‌کنید، `app_url` باید آدرس **همان زیردامنه HTTPS** باشد. پورت 8080 برای سایت تنظیم نمی‌شود؛ کاربران HTTPS استاندارد را باز می‌کنند.

در زرین‌پال، درگاه دامنه را فعال و Merchant ID را در `merchant_id` فایل خصوصی config.php قرار دهید. برای آزمایش `sandbox => true` و پس از تست و تأیید درگاه اصلی `sandbox => false` تنظیم شود. callback:

```text
https://sadatpakhsh.ir/api/payment/callback
```

قیمت‌ها در فروشگاه تومان و در ارتباط درگاه ریال‌اند. هیچ اطلاعات کارت در دیتابیس ذخیره نمی‌شود. پیام پارامتر URL به‌تنهایی پرداخت را تأیید نمی‌کند. مدیر در سفارش‌های معلق می‌تواند «بررسی مجدد پرداخت» را بزند؛ نتیجه فقط با پاسخ سرور زرین‌پال ثبت می‌شود.

تا مرچنت واقعی وارد نشده، ثبت درخواست پرداخت عمداً متوقف می‌شود. تست واقعی Sandbox و پرداخت اصلی روی هاست شما انجام نشده و باید پیش از فروش عمومی انجام شود. این کد برای زرین‌پال است، نه درگاه مستقیم بانک دیگر.

## ۶. نگهداری و محدودیت‌ها

- از **دیتابیس جدید و پوشه storage/uploads با هم** پشتیبان بگیرید. storage/sessions نیز خصوصی است؛ در بسته دانلود عمومی قرار نگیرد.
- Cron سفارش‌ها، Uploadهای WebP بدون ارجاع را پس از مهلت امن ۲۴ ساعت شناسایی و حداکثر ۲۰۰ فایل را در هر اجرا پاک می‌کند؛ نتیجه در Log ثبت می‌شود.
- سوابق ورود نام حساب، زمان و مرورگر اعلام‌شده را ثبت می‌کنند؛ IP و رمز خام ثبت نمی‌شوند. رویدادهای بیش از ۹۰ روز هنگام ورود بعدی پاک می‌شوند.
- در استقرار روی چند سرور، فایل نشست‌ها و تصاویر باید ذخیره‌سازی مشترک داشته باشند؛ این بسته برای همین هاست تکی است.
- کاتالوگ عمومی با صفحه‌بندی ۲۴ کالا و شمارش کل پیاده شده است. فهرست‌های مدیریتی هنوز به ترتیب ۵۰۰ محصول/کاربر، ۲۰۰ سفارش و ۱۰۰ رویداد اخیر را نشان می‌دهند و در مقیاس بزرگ باید Cursor Pagination مدیریتی نیز اضافه شود.
- داده‌های محلی Next.js خودکار به MySQL منتقل نمی‌شوند؛ هیچ دیتابیس قبلی پاک نشده است. برای انتقال داده واقعی باید خروجی و نگاشت جداگانه بررسی شود. نصب تازه شامل محصولات نمونه است.

## ۷. آزادسازی خودکار سفارش‌های رهاشده

کد این قابلیت داخل `naylex-app/cron-expire.php` قرار دارد. فعال‌شدن زمان‌بندی روی هاست نیازمند اضافه‌کردن Cron Job است؛ صرفاً آپلود فایل کافی نیست. تغییر ساختار دیتابیس یا نصب مجدد لازم نیست. هنگام ارتقا، فایل‌های برنامه را جایگزین کنید و `config.php` و `storage` خودتان را نگه دارید.

در `naylex-app/config.php` داخل آرایه تنظیمات اضافه کنید (پیش‌فرض بدون این خط هم ۳۰ دقیقه است):

```php
'reservation_minutes' => 30,
```

پس از این مهلت، سفارش بدون شناسه درگاه آزاد می‌شود. برای سفارش دارای شناسه، ابتدا وضعیت از زرین‌پال استعلام می‌شود: پرداخت موفق با تأیید مبلغ ثبت می‌شود؛ FAILED یا REVERSED موجودی را آزاد می‌کند؛ IN_BANK، پاسخ ناشناخته یا خطای شبکه موجودی را رزرو نگه می‌دارد تا اجرای بعدی. بنابراین آزادسازی برای همه سفارش‌ها دقیقاً در دقیقه ۳۰ تضمین نمی‌شود. اجرای تکراری موجودی را دوباره افزایش نمی‌دهد.

اگر پرداخت دیرهنگام پس از آزادسازی در callback یا بررسی مدیر تأیید شود، موجودی دوباره به صورت تراکنشی رزرو می‌شود. در صورت کمبود، سفارش با شناسه پرداخت و وضعیت «پرداخت دریافت شده؛ نیازمند تأمین موجودی یا استرداد» نمایش داده می‌شود و قابل ارسال نیست. مدیر باید موجودی را تأمین و دوباره پرداخت را بررسی کند یا استرداد را از زرین‌پال پیگیری کند؛ استرداد خودکار نیست.

در cPanel بخش **Cron Jobs**، زمان‌بندی را هر ۵ دقیقه (`*/5 * * * *`) انتخاب کنید و در قسمت **Command** فقط دستور زیر را قرار دهید:

```sh
/usr/local/bin/php /home/rrjjboqm/naylex-app/cron-expire.php >> /home/rrjjboqm/naylex-app/storage/expiry-cron.log 2>&1
```

این مسیر PHP یک نمونه است؛ از پشتیبانی بخواهید مسیر **PHP CLI نسخه 8.2 با pdo_mysql و curl** را تأیید کند. در هاست CloudLinux ممکن است مسیر `/opt/alt/php82/usr/bin/php` باشد. مسیر home را نیز از File Manager بررسی کنید. این فایل خارج از public_html است و با آدرس مرورگر اجرا نمی‌شود.

لاگ خصوصی `storage/expiry-cron.log` باید هر پنج دقیقه خطی با زمان UTC و شمارنده‌های `released` (آزادشده)، `paid` (پرداخت تأییدشده)، `deferred` (به تعویق افتاده)، `skipped` و `errors` داشته باشد. errors غیرصفر یا تکرار deferred را بررسی کنید؛ فایل لاگ را دوره‌ای بایگانی کنید. هر اجرا حداکثر ۱۰۰ سفارش را بررسی می‌کند و ادامه کار را به اجرای بعدی می‌سپارد؛ اجرای هم‌زمان با قفل مهار می‌شود.

## ۸. بازکردن و تست روی همین کامپیوتر

فایل PHP را با دوبار کلیک یا Live Server اجرا نکنید. اگر سرورهای محلی فعلی روشن‌اند، در مرورگر باز کنید:

- فروشگاه: http://localhost:8085
- پنل: http://localhost:8085/admin
- اطلاعات ورود مدیر آزمایشی: فایل `.runtime/php-local-admin.json` در ریشه پروژه؛ فقط برای محیط محلی است.

برای اجرای دوباره پس از خاموش‌کردن کامپیوتر، در VS Code از **Terminal → New Terminal** دو ترمینال PowerShell باز کنید. این دستورها مخصوص همین پروژه و XAMPP نصب‌شده در `C:\xampp` هستند و از دیتابیس آزمایشی جداگانه استفاده می‌کنند.

ترمینال اول (باز بماند):

```powershell
cd D:\sadat_pakhsh
& C:\xampp\mysql\bin\mysqld.exe --defaults-file=D:\sadat_pakhsh\.runtime\php-mysql\my.ini --bind-address=127.0.0.1 --port=33077 --console
```

ترمینال دوم (باز بماند):

```powershell
cd D:\sadat_pakhsh
& C:\xampp\php\php.exe -d extension=gd -d upload_tmp_dir=D:/sadat_pakhsh/.runtime/php-upload-tmp -d upload_max_filesize=5M -d post_max_size=6M -S localhost:8085 -t php-store/public_html php-store/router.php
```

اگر پیام «port already in use» آمد، نمونه دیگری را اجرا نکنید؛ سرور قبلی و آدرس مرورگر را بررسی کنید. برای توقف ترمینال Ctrl+C بزنید. این تنظیمات محلی و رمز دیتابیس محلی را به هاست منتقل نکنید.

برای تست خودکار آزادسازی، در ترمینال سوم اجرا کنید:

```powershell
cd D:\sadat_pakhsh
& C:\xampp\php\php.exe scripts/php-expiry-tests.php
```

۱۲ سناریو از جمله آزادسازی، اجرای تکراری، پرداخت موفق، پرداخت دیرهنگام، کمبود موجودی و قطع شبکه با پاسخ شبیه‌سازی‌شده درگاه و MySQL واقعی محلی بررسی می‌شود. داده‌های آزمون بعد از پایان حذف می‌شوند. این دستور روی دیتابیس هاست اجرا نمی‌شود. برای یک بار اجرای کار زمان‌بندی‌شده محلی:

```powershell
& C:\xampp\php\php.exe php-store/naylex-app/cron-expire.php
```

تست انتهابه‌انتهای زرین‌پال همچنان نیازمند مرچنت معتبر و محیط Sandbox است: یک سفارش را پرداخت کنید، یکی را رها کنید و تغییر وضعیت سفارش و موجودی و لاگ Cron را پس از مهلت کنترل کنید. داده یا موجودی واقعی را برای تست دستی دست‌کاری نکنید.

## رفع اشکال

**تغییرات ورود و سبد:** حداقل رمز حساب ۸ کاراکتر است. ثبت‌نام با شماره یا نام ثبت‌شده پیام «شما قبلاً حساب دارید» نشان می‌دهد. کنترل‌های سبد، قیمت عمده، هزینه ارسال و جمع مبلغ را دوباره از سرور محاسبه می‌کنند. ورود مدیر در صورت فعال‌سازی 2FA به کد Authenticator یا کد بازیابی نیاز دارد.

**بازیابی پیامکی:** بنا به تصمیم فعلی مدیر، سرویس پیامکی هنوز تهیه و پیکربندی نشده است. لینک `/forgot-password` فعال است اما ارسال کد و تغییر رمز با پیامک فعال نیست؛ پس از انتخاب سرویس، اتصال و تأیید کد باید پیاده‌سازی و تست شود.

**هماهنگی مدیر محلی با .env:** حساب مدیر همین محیط محلی با `ADMIN_USERNAME` و `ADMIN_PASSWORD` هماهنگ شده است. اگر این دو مقدار را بعداً تغییر دادید، در ریشه پروژه اجرا کنید: `& C:\xampp\php\php.exe scripts/sync-php-admin.php`. این ابزار فقط دیتابیس آزمایشی محلی را قبول می‌کند و رمز را به‌صورت هش ذخیره می‌کند؛ روی هاست اجرا نمی‌شود. تغییر `.env` به‌تنهایی رمز حساب PHP را تغییر نمی‌دهد.

**سبد خرید:** با JavaScript فعال، افزودن محصول بدون تغییر صفحه انجام می‌شود و تعداد زیر محصول به‌روز می‌شود. با نگه‌داشتن موس روی سبد یا دکمه «نمایش سبد» در موبایل، تصویر، توضیح کوتاه، تعداد و قیمت محصولات را می‌بینید. برای دیدن تغییرات فایل CSS و JavaScript، Ctrl+F5 بزنید.

**خطای اتصال دیتابیس:** نام کامل دارای پیشوند، رمز کاربر و Add User To Database را بررسی کنید. رمز حساب cPanel لزوماً رمز MySQL نیست.

**404 برای /products یا /admin:** فایل مخفی .htaccess منتقل نشده، mod_rewrite خاموش است یا قواعد وردپرس قدیمی هنوز فعال‌اند. در document root صحیح فقط قواعد همین بسته را پس از پشتیبان‌گیری قرار دهید.

**403 هنگام ذخیره یا «مبدأ درخواست مجاز نیست»:** هدر `Referrer-Policy` باید `strict-origin-when-cross-origin` باشد. مقدار `no-referrer` برای ارسال فرم در مرورگر می‌تواند Origin را به `null` تبدیل کند. فایل‌های اصلاح‌شده `naylex-app/bootstrap.php` و `public_html/.htaccess` را با هم منتقل کنید و با Ctrl+F5 فرم را دوباره باز کنید. کنترل CSRF یا Origin را حذف نکنید. app_url محلی باید `http://localhost:8085` و روی هاست `https://sadatpakhsh.ir` باشد؛ `.env` مربوط به نسخه Next.js است و تنظیمات PHP از `naylex-app/config.php` خوانده می‌شود.

**ثبت‌نام و مدیریت:** ثبت‌نام مشتری عادی در `/register`، درخواست همکاری در `/wholesale`، ورود مشتری و مدیر در `/login` است. پس از ورود مدیر، برای افزودن محصول همراه عکس، قیمت و موجودی از `/admin?tab=products&edit=0` استفاده کنید. اطلاعات شرکت و متن درباره ما در `/admin?tab=company` قابل ویرایش است. نام کاربری و رمز مدیر همان مقادیر انتخاب‌شده در نصب PHP هستند؛ حساب Next.js خودکار منتقل نشده است.

**آپلود ناموفق:** GD/WebP، fileinfo، upload_max_filesize، post_max_size، پوشه موقت PHP و مجوز نوشتن storage را بررسی کنید. متن دقیق خطا در صفحه نشان داده می‌شود؛ اطلاعات محرمانه را عمومی ارسال نکنید.

**نصب قبلی بدون installed.lock:** پس از تأیید کامل‌بودن جدول‌ها و حساب مدیر توسط مسئول فنی، نشانگر نصب را بازیابی کنید؛ با اجرای نصب مجدد یا حذف داده‌ها مشکل را حل نکنید.

## محتوا و سئوی فروشگاه

### جستجوی سریع و مدیریت مقاله

با تایپ حداقل دو حرف در کادر جستجو، حداکثر شش محصول فعال همراه تصویر، قیمت خرده و واحد فروش زیر همان کادر نمایش داده می‌شوند. با کلیک یا کلیدهای جهت‌دار و Enter وارد محصول می‌شوید؛ دکمه جستجو همچنان صفحه نتایج کامل را باز می‌کند.

مدیر از `/admin?tab=articles` مقاله‌ها را مدیریت می‌کند و از `/admin?tab=articles&edit=0` مقاله تازه می‌نویسد. عنوان، شناسه انگلیسی آدرس مثل `trash-bag-selection`، خلاصه، متن کامل، دسته مرتبط و تصویر JPEG/PNG/WebP را وارد کنید. متن به‌صورت امن و ساده با حفظ خط‌های جدید نمایش داده می‌شود؛ HTML اجرا نمی‌شود. تصویر حداکثر ۵ مگابایت است و هنگام ذخیره به WebP تبدیل می‌شود.

تیک «انتشار» را بردارید تا مقاله پیش‌نویس باشد. مقاله منتشرشده در `/articles`، صفحه اختصاصی و نقشه سایت ظاهر می‌شود. آدرس مقاله ذخیره‌شده ثابت است تا لینک‌های قبلی خراب نشوند. شش راهنمای اولیه `/guides` در فایل guide-content.php باقی می‌مانند و بخش مقاله برای مطالب جدید مدیر است.

در انتشار این نسخه، جدول جدید `ns_articles` خودکار با `CREATE TABLE IF NOT EXISTS` ساخته می‌شود؛ کاربر دیتابیس به مجوز CREATE نیاز دارد. نصب‌کننده را دوباره اجرا نکنید. همه فایل‌های جدید articles.php و search.php همراه کدهای تغییرکرده منتقل شوند. config.php و storage موجود هاست حفظ شوند. برای به‌روزرسانی با Git، پس از commit و push، در cPanel «Update from Remote» سپس «Deploy HEAD Commit» را اجرا کنید.

عنوان صفحه اصلی اکنون «نایلکس سادات _ خرید عمده و خرده نایلون و نایلکس» است. گوگل می‌تواند عنوان نتیجه را بازنویسی کند. پس از انتشار، URL Inspection صفحه اصلی و دسته‌های اصلی را بررسی کنید و sitemap.xml را ثبت کنید. نمایش سایت با نام برند به‌تنهایی علت رتبه نگرفتن کلمات عمومی را مشخص نمی‌کند؛ گزارش Performance و Pages در Search Console برای تشخیص لازم است. تغییر عنوان یا پیشنهادهای جستجوی داخلی تضمین رتبه در گوگل نیست.

صفحه‌های راهنمای خرید در `/guides` و صفحه عمومی همکاری عمده در `/wholesale-buying` هستند. این دو مسیر و مقاله‌هایشان به‌صورت خودکار در `/sitemap.xml` قرار می‌گیرند. برنامه کلمات کلیدی، روش تکمیل کالاها و کارهای ماهانه در [SEO-KEYWORD-PLAN-FA.md](SEO-KEYWORD-PLAN-FA.md) آمده است.

برای تکمیل سئوی محلی، از پنل مدیر → «اطلاعات شرکت» تلفن، نشانی کامل قابل انتشار، ساعت پاسخ‌گویی و کد پستی را وارد کنید. نشانی اولیه «تهران، مجتمع تجریشی» فقط تا زمان ذخیره نشانی دقیق‌تر نمایش داده می‌شود.
